## 1. Summary
Wazuh raised rule 60122 alerts for Windows Event ID 4625 on the lab endpoint. The failed logons were local interactive sign-in attempts with a wrong PIN, generated on purpose to test detection.

## 2. Detection
- Alerts: rule 60122 on agent `dell-windows`, Security channel, Event ID 4625
- Event Viewer: 5 failed logons in the filtered view (06/11, 08/11, and 2 on 09/11 at 19:29:58 and 19:30:00)

## 3. Analysis
- Logon type 2 (interactive), source IP 127.0.0.1, process svchost.exe → local attempt at the machine, not over the network
- Status 0xC000006D with sub-status 0xC0000380 → wrong PIN (Windows Hello / smart card)
- Target account not resolved (SID S-1-0-0)
- The attempts match my own test at the lock screen → **true positive, benign (authorized test)**

## 4. Impact
None. Local test attempts only, no remote source, no unauthorized access.

## 5. Response / recommendation
- No containment needed
- In a real environment: check for a following successful logon (Event ID 4624) from the same source, check the account lockout policy, and contact the user

## 6. Lessons learned
- **Clock drift:** the Wazuh VM clock was out of sync, so the Manager timestamps (04:07) did not match the Windows event time (19:30). Fixed by enabling NTP (`timedatectl`: *System clock synchronized: yes*). Correct timestamps are essential for timelines.
- **MITRE mapping:** default mappings should be reviewed by the analyst (T1531 vs T1110).
- **Next detection improvement:** custom threshold rule for repeated 4625 events on the same host.
